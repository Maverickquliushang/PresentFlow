# 架构与状态

`code/src/presentflow` 是可安装包；`code/skills/presentflow` 是通用 AI 工作流。通用版不依赖任何特定论文、开发者电脑、个人录音或已有缓存。

| 模块 | 职责 |
|---|---|
| ingest | PDF 文字层、PPTX 实际页序/备注/对象清单、逐页稿读取 |
| planning | 场景分类、部分备注识别、冲突处理、分阶段缺失问题 |
| hardware | 系统/RAM/NVIDIA 显存检测与可解释的建议 |
| authoring / native | 检查 AI talk spec，原生制片、模板文本替换或仅写备注 |
| voice / engine | provider 选择、试听批准、缓存、本地 Qwen、背景和免宏装配 |
| consent / cloud | 按服务/用途/数据哈希授权，官方 API 调用、累计字符预算 |
| storage / cli | 私有任务状态与统一命令 |

任务 `job.json` 保存输入引用、用户已答需求、当前产物引用。原文档不修改；任务包含个人资料，应放在 `runs/` 或其他私有目录。`private/` 中的来源清单、consents、voice ID、音频和验证记录均不属于代码。

阶段顺序：材料 → 汇报需求 → 品牌 → 讲稿权威版本 → 是否配音 → 部署/服务选择 → 录音 → 试听 → 整场语音 → 装配/检查。`questions_now` 只给当前阶段最多三项；内容创作可与不依赖它的环境检测并行。用户明确不配音时跳过所有配音阶段。

生成 PPT / 写稿是 AI 助手的职责，不把命令行场景判断伪装成生成式模型。需要连接独立写作模型或网页前端时，可围绕 `make_plan` 与结构化 talk spec 扩展；当前不内置自动上传论文的文本模型 API。

配音缓存按实际文本、读音、模型权重/参数、参考音色和校验设置签名；任务中页末停顿一次选取，改稿复用原停顿。背景根据新的实际音频长度重建。云缓存含 model、voice 和语音参数；失败不会无限重试。在线预算为任务累计请求字符，不是货币报价。

授权不能由硬件检测或上传附件推断。录音上传、试听文本、完整讲稿分别展示 scope，执行端在网络请求前校验。改稿、换服务、换模型/音色对应 payload 改变时旧授权不匹配。本地方案不借用云兜底；只有接收端能验证的请求状态也会保留预算，防止断线重跑无意计费。

新增语音服务时应提供：能力/语言和素材要求、外发数据摘要、preview/full 一致的缓存、服务专属授权、费用上限、失败停止点。模型权重或素材不能随代码自动再分发。
